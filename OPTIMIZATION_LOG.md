# Local-control iteration log

Purpose: remember where the Muse-to-PC control stack gets stuck, then
self-optimize from the record. Each entry: date, component, symptom,
impact, root cause, fix/status. The tunnel watchdog appends every restart
to `tunnel-restarts.log`; this file is the human-readable record and the
place fixes get decided. Review it on every learning batch and whenever
something in the stack breaks.

## How the loop works (corrected 2026-11-17 18:10 — see correction entry below)
1. On demand only: before a desktop task, Muse runs `ensure-tunnel.sh`; it
   starts the tunnel if 18000 is not listening, and reports up/down. There
   is NO cron and NO polling — the user rejected the 5-minute check (288 agent
   runs/day would burn the token quota). Verified 2026-11-17: no watchdog cron
   exists in `cron.list`.
2. Self-healing while running: `mcp-tunnel.sh` is a shell loop, not a single
   ssh. If ssh drops after a real connection, it reconnects with backoff
   (5s doubling to 60s). If the PC was never reachable, it gives up after
   10 consecutive fast failures and exits; the next on-demand check retries.
   No agent, no tokens while it runs.
3. Every (re)start / drop / give-up is appended to `tunnel-restarts.log`.
4. Review happens on the next desktop session, not on a schedule: when
   something in the stack breaks, read the log, fix the cause, record it
   here — don't just restart and forget. No weekly review cron is created
   (same token reason as the 5-minute check).
